# Макора

Макора — демонстрационный интерфейс подготовки хакатонного проекта: анализ задания, исследование и идея, план разработки и мок-данные. В интерфейсе используется вымышленный кейс «Тихий кампус»; загруженное условие не анализируется моделью, а демонстрационный план и фикстуры не перестраиваются после изменения идеи.

## Запуск сайта

Из корня репозитория запусти локальный сервер Макоры (Python 3.11 или новее):

```sh
python -m makora_core.server --static dist --workspace ~/.makora/workspace --host 127.0.0.1 --port 8000
```

Открой [localhost:8000](http://localhost:8000/). Локальный API и сайт работают на одном порту. История хранится в указанной папке вне репозитория; ZIP и документы не отправляются в облако. На Windows укажи, например, `--workspace "$env:LOCALAPPDATA\Makora\workspace"`.

После появления доски под Макорой находится меню **«Возможности» → «Рабочий прототип»**. Оно собирает актуальные материалы и `changeset.schema.json`, сохраняет базовый ZIP и создаёт итерацию. Вернув ZIP, пользователь видит список добавленных/изменённых/удалённых файлов, текстовые diff или хеши бинарных файлов, этапы-кандидаты на перепроверку, различия с `changeset.json`, вопросы и статусы из `prototype-report.json`. Для каждого изменения доступны **Принять / Доработать / Отклонить**.

Принятые изменения, затрагивающие артефакты этапов, формируют отдельный ZIP актуализации с исходными документами, diff, решениями и зависимостями. Внешний ИИ возвращает документы в `proposals/` и `adaptation-report.json`; Макора проверяет структуру, пути, пустые файлы, JSON/YAML-синтаксис там, где валидатор доступен, затем просит отдельно утвердить каждый документ. Новая ревизия создаётся только после разрешения всех изменений, вопросов, зависимостей и документов. Следующий цикл включает последнюю согласованную версию проекта и новый контекст Макоры. История сохраняется между перезапусками; откат создаёт новую ревизию и не удаляет прежние.

Макора не запускает код из ZIP и не считает заявленные тесты выполненными автоматически: отчёт внешнего ИИ отображается как его заявление, а запуск кода — `not_checked`. Необъяснённые изменения и неподтверждённые решения видны пользователю. Если используется обычный статический сервер вместо API Макоры, сравнение, история и утверждение недоступны; интерфейс сообщает об этом. Для ручного запуска API рядом со статикой используй `python -m makora_core.server --workspace ~/.makora/workspace --port 8765`.

В меню **«Возможности» → «Тестовый кейс»** доступен отдельный учебный пакет «Доступный город» с промптом, схемами, контрактом, тест-планом и синтетическими фикстурами. Его состояние хранится отдельно от основного проекта. Скачанный пакет можно передать внешнему ИИ и вернуть результат в тот же пункт меню.

Пункт «Тестовый кейс» пока использует отдельный демонстрационный сценарий браузера: он сохраняет возвращённый ZIP и задаёт вопросы о `new_mocks/`, но не подключён к истории локального API. Полный цикл V1 → карта → согласование документов → V2 для этого кейса воспроизводится автоматическим тестом `test_accessible_city_map_v1_to_v2_and_repeat_handoff`. Рабочий цикл с историей доступен в пункте «Рабочий прототип».

Промпт требует сохранить исходную `mocks/`, использовать её как источник данных и помещать новые данные отдельно в `new_mocks/`. Возвращённый ZIP сравнивается по фактическим путям и содержимому, включая изменения исходных моков. Ссылки не загружаются автоматически.

Зарегистрированные связи в `artifact-links.json` задаются как `{"links":[{"from":"02_solution_concept.md","to":"03_architecture.md"}]}`: изменение `from` помечает `to` и его последующие зависимости для перепроверки. Чтобы изменить связи, верни обновлённый файл и отдельно прими его изменение. Если зарегистрированной связи нет, этап определяется по пути файла как предположение. Кнопка **«Файлы версии»** на доске открывает документы соответствующего этапа из сохранённой текущей ревизии. Учебные разделы доски при этом не перезаписываются автоматически.

## Скиллы и артефакты

В `skills/` находятся восемь самостоятельных инструкций, включая `change-reconciliation`. Они описывают работу внешнего агента, но встроенная модель не подключена. Схема `changeset.json` доступна в `dist/changeset.schema.json` и `skills/change-reconciliation/assets/`. Локальное API использует JSON-индекс и неизменяемые ZIP-снимки. Хранилище по умолчанию нужно размещать вне репозитория; не помещай конфиденциальные документы в публичный Git.

## Проверки

Для Python-проверок установите зависимость и выполните тесты:

```sh
python -m pip install -r requirements-dev.txt
python scripts/check_skills.py
python -m unittest discover -s tests -v
```

Тесты `test_iterations.py` и `test_iteration_api.py` проверяют версии, diff, решения, конфликты зависимостей, актуализацию документов, устаревшую базу, перезапуск, откат, HTTP API и отказ опасным ZIP. Браузерный маршрут в CI использует тот же API-сервер, что и локальная установка.

В `tests/fixtures/` находятся учебные входы и вручную подготовленные ожидаемые результаты для восьми скиллов. Тесты проверяют форматы и связи между этапами; примеры не являются результатами выполнения ИИ. GitHub Actions запускает Python-тесты, проверку скиллов и браузерные сценарии при push и pull request.

Скрипт [`tests/browser-flow.js`](tests/browser-flow.js) проверяет демонстрационный маршрут в отдельном браузерном профиле через Playwright CLI. Запустите сайт, затем:

```sh
npx --yes --package @playwright/cli playwright-cli -s=makora-smoke open http://127.0.0.1:8000/
npx --yes --package @playwright/cli playwright-cli -s=makora-smoke run-code --filename tests/browser-flow.js
npx --yes --package @playwright/cli playwright-cli -s=makora-smoke run-code --filename tests/handoff-wait.js
npx --yes --package @playwright/cli playwright-cli -s=makora-smoke run-code --filename tests/handoff-new-mocks.js
npx --yes --package @playwright/cli playwright-cli -s=makora-smoke run-code --filename tests/example-case.js
npx --yes --package @playwright/cli playwright-cli -s=makora-smoke close
```

Сценарий сбрасывает `localStorage` только в созданном профиле Playwright. Проверки фикстур и mock API подтверждают работу демонстрационных данных, а не будущего продукта.
