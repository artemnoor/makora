# Макора

Макора помогает пройти путь от исходного кейса до разработки приложения агентами Codex: объяснить задачу, изучить аналоги, собрать идею человека, подготовить данные и организовать работу по согласованному плану.

Сайт работает локально и связан с одной папкой проекта Codex Desktop. На доске видны семь этапов; содержание открывается по нажатию на этап. Обсуждение идеи проходит в чате Codex, а согласованные документы появляются в Макоре.

## Быстрый запуск

Нужны Python 3.11+, Node.js 22.13+, PowerShell 7, Git и авторизация Codex. Реальные запросы моделей расходуют лимиты вашей подписки.

Откройте папку проекта в Codex Desktop и отправьте:

> Склонируй https://github.com/artemnoor/makora.git в подпапку makora. Прочитай AGENTS.md и установи Макору для текущей папки проекта через setup.ps1. Запусти локальный сервер, проверь состояние и дай ссылку на сайт. Затем используй навык makora-control.

Для ручной установки из корня клонированного репозитория:

```powershell
./setup.ps1 -ProjectRoot 'C:\Projects\Campus'
```

Здесь `Campus` — папка вашего проекта Codex, а репозиторий может находиться внутри неё в `makora`. Установщик создаёт окружение, устанавливает зависимости и проектные навыки, затем запускает сайт. Другой порт задаётся параметром `-Port 8001`.

На сайте загрузите PDF/DOCX/TXT/MD с кейсом или вставьте текст. Запустите простое объяснение и двигайтесь по доске. Подробности установки, ограничения файлов и обновление — в [руководстве первого запуска](docs/getting-started.md).

## Как устроен маршрут

1. **Простое объяснение.** Короткое изложение задачи с примером. Ограничения появляются только при их прямом наличии в кейсе и подтверждаются цитатами.
2. **Поиск аналогов.** Сравнение похожих продуктов и источников, решения пользователя и выгрузка PDF. Можно продолжить без исправлений с сохранением пометок о непроверенных сведениях.
3. **Брейншторм.** Пользователь обсуждает идеи с ИИ в отдельном чате проекта Codex. После «готово» ИИ предлагает версии, экраны и переходы; отдельное подтверждение разрешает публикацию документов.
4. **Мок-данные.** Фикстуры, схемы и сценарии под все согласованные версии и экраны.
5. **Пакет для агента.** ZIP с материалами и промптом. Вернувшийся проект проверяется и подготавливается как основание дальнейшей работы.
6. **Планирование.** Граф общего каркаса, основных задач и выбранных человеком лабораторий. Задачи и связи можно редактировать до запуска разработки; правки требуют нового утверждения.
7. **Разработка агентами.** Исполнение утверждённого графа с отдельными рабочими копиями, независимыми тестами, ревью и проверяемой интеграцией.

Готовый ответ ИИ, проверенный документ и утверждённый результат — разные состояния. Повторная проверка уже завершённого этапа не требует нового запроса к модели. [Полное описание этапов →](docs/stages.md)

## Лаборатории

Лаборатория — отдельная ветвь работы над сложной функцией с небольшим интерфейсом для проверки человеком. Например, можно отдельно разрабатывать поиск, пока основной каталог работает на моковых результатах.

Лаборатории необязательны: человек выбирает функции и правит схему. После общего каркаса независимые лабораторные и основные задачи могут выполняться параллельно. Готовый результат проходит тесты, ревью и человеческую приёмку, привязанную к проверенному коду.

Тестовые файлы из `labs/<id>/` не включаются в коммит интеграции лабораторной функции. Отдельная задача подключает функцию к приложению и проверяет финальную сборку. Переключение с моков на реализацию должно быть предусмотрено в коде приложения.

[Жизненный цикл, пример схемы и приёмка лабораторий →](docs/laboratories.md)

## Управление из Codex

Попросите применить установленный навык `makora-control`. Он обращается к тому же состоянию проекта, что и сайт, и умеет проверять состояние, запускать и утверждать этапы, менять настройки и управлять разработкой.

Проверка из корня установленного репозитория:

```powershell
./.venv/Scripts/python.exe scripts/makora.py --project-root 'C:\Projects\Campus' status
```

Модель и уровень рассуждений выбираются отдельно для каждой роли в настройках проекта. Изменения применяются к новым сессиям; модель уже открытого чата Desktop выбирается в самом Codex.

## Разработка и проверки

Основной код находится в `makora_core/`, интерфейс — в `dist/`, навыки — в `skills/`. Перед изменениями прочитайте [AGENTS.md](AGENTS.md) и [руководство разработчика](docs/development.md).

```powershell
python -m pip install -r requirements-dev.txt
npm ci
python scripts/check_skills.py
python -m unittest discover -s tests -q
node tests/test_project_restore.mjs
```

CI дополнительно выполняет браузерные сценарии. Проверки интерфейса с подменёнными ответами не доказывают прохождение реального агентного цикла. Сессии моделей проверяются отдельно на выделенных тестовых проектах.

Не публикуйте пользовательское состояние `.makora/`, личные кейсы и секреты авторизации. Состояние и документы проекта сохраняются между запусками; удалять их для обновления интерфейса не требуется.
