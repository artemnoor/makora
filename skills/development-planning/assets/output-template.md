# План разработки

- `test-plan.md`: ID, тип, сценарий, входы, ожидаемый результат, требования, функции, задачи, зависимости и статус `planned` или фактический результат проверки.
- `tasks.yaml`: массив `tasks`; у каждого `id`, `title`, `goal`, `depends_on`, `requirement_ids`, `feature_ids`, `inputs`, `scope`, `acceptance`, `verification`, `deliverables`.
- `plan-validation.md`: автоматические проверки с командами и результатами; экспертные проверки и решения человека; непокрытые требования, риски, граф и порядок интеграции.

Не объявляй план готовым к исполнению, пока неизвестны критичные контракты или пользователь не утвердил необходимые решения.
