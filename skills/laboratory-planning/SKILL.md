# Основная ветка и лаборатории

Изучи возвращённый проект и согласованные версии/экраны, моки и laboratoryPreferences. Пользователь сам выбирает функции для лабораторий. Не создавай обязательные лаборатории по собственной инициативе; без пожеланий верни laboratories: [] и объясни, как их добавить в редакторе схемы.

В `03_tasks.json` — tasks с обычными полями id, title, goal, acceptance, dependsOn, contracts, mocks, allowedPaths, builderPrompt, testPrompt, reviewerPrompt. В `03_execution.json` — `{ "skeletonTaskId":"BASE", "laboratories":[] }`. Первая задача каркаса имеет dependsOn: []; остальные задачи зависят от неё прямо или транзитивно. Разделяй файлы независимых задач: общие файлы меняются отдельной задачей интеграции. Граф должен допускать параллельную работу основной ветки и лабораторий, а не ставить все основные задачи в зависимость от лаборатории.

Лаборатория: `{ "id":"OCR", "title":"Распознавание", "taskIds":["OCR_FEATURE"], "uiRoot":"labs/OCR/", "previewCommand":["node","labs/OCR/preview.mjs"], "mockFixture":"mocks/fixtures/data.json", "integrationTaskId":"JOIN_OCR" }`.

Её feature-задача создаёт рабочую функцию в отдельных файлах приложения и мини-интерфейс в labs/<id>/. Все файлы, включая preview-скрипт, перечислены в allowedPaths. Скрипт запускает локальный тестовый интерфейс на 127.0.0.1 с портом из переменной PORT и использует настоящую функцию лаборатории. Данные тестового интерфейса и ошибки должны позволять человеку проверить её поведение; не выдавай мок за результат функции. Не устанавливай зависимости в preview-скрипте.

Основной каркас использует mockFixture вместо незавершённой функции. Отдельная integrationTaskId зависит от всех задач лаборатории: после проверки человеком подключает настоящую функцию вместо моков. Пока лаборатория в разработке или ещё не подключена, основной сценарий продолжает работать на моках. Тесты каркаса проверяют этот режим.

UI лаборатории тестовый: основной интерфейс не ссылается на labs/, production-сборка не импортирует эти файлы. Контроллер не переносит labs/<id>/ при интеграции feature-задачи. Общая реализация функции лежит вне uiRoot, а рабочие файлы не должны импортировать тестовый UI. Приёмочные тесты integrationTaskId проверяют отсутствие тестовых экранов/маршрутов в финальной версии.

Для каждой ветви укажи, что делает агент, что проверяют тесты и что проверяет человек. Не запускай агентов из этапа планирования. Человек может редактировать задачи, зависимости и состав лабораторий перед утверждением.
