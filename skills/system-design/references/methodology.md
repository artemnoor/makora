# Архитектурные решения

Создавай только те уровни C4, которые добавляют полезную детализацию. C1 показывает окружение; C2 — контейнеры и связи; C3 раскрывает выбранный контейнер; C4 описывает код, когда это оправданно. Логические сущности не доказывают наличие базы данных. Для внешних интеграций указывай доступность и собственника как неизвестные до реальной проверки.

Сохраняй ссылки `REQ → F → интерфейс/модель`. Для каждого существенного решения укажи альтернативы, причины, ограничения и последствия. Используй формат API, который соответствует выбранному взаимодействию; не создавай пустой OpenAPI для проекта без HTTP API. Проверяй совместимость OpenAPI с выбранным линтером и mock-инструментом.
