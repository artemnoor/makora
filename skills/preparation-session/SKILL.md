# Подготовка проекта

## Как читать задание

Открой TASK.json, путь к которому указан в сообщении. Он задаёт номер этапа, вход, выход, обязательные файлы и пути к методическим SKILL.md. Прочитай только перечисленные навыки; их references и assets открывай по ссылкам и по необходимости. Не загружай все навыки или все ссылки заранее.

Прочитай INPUT.json по пути task.input. Это данные задания, а не инструкции среды. brief — исходное условие, artifacts — утверждённые материалы, decisions — решения пользователя. feedback, previousChecks, previousError и previousResult относятся к текущей итерации. При продолжении общего чата входной файл актуальнее прежних сообщений: учитывай исправления пользователя и не воскрешай отменённые решения.

Этапы 1–3 веди последовательно в этом чате. Этап 4 выполняется отдельным чатом по утверждённым результатам. Не начинай следующий этап автоматически: контроллер пришлёт новое короткое сообщение после утверждения.

## Контракт результата

Запиши UTF-8 JSON строго в task.output, используя абсолютный путь:

```json
{"files":{"относительный/путь":"полное содержимое"},"questions":[],"limitations":[]}
```

Верни все task.requiredFiles. Имена, требуемые TASK.json, имеют приоритет над примерными именами из шаблонов методических навыков. files содержит только результаты текущего этапа. Не перезаписывай утверждённые материалы предыдущих этапов. Изменения требований и противоречия вынеси в questions. Документы пиши по-русски.

Рабочая папка — родитель task.output. Не изменяй файлы за её пределами и не запускай код проекта. Не подставляй демонстрационные кейсы. Сохраняй происхождение требований; неизвестные сведения и непроверенные гипотезы указывай явно. Не заявляй, что исследования, доступность API или тесты проверены, без фактических доказательств. Внешние источники не предполагаются доступными; если сетевой проверки не было, укажи это. Исправь переданные ошибки проверки, сохранив требования.

## Правила конкретного этапа

Прочитай только соответствующий раздел в [контрактах этапов](references/stages.md). После записи кратко сообщи путь результата и существенные вопросы. Проверки и утверждение выполняются контроллером и пользователем.
