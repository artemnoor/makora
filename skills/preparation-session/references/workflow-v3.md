# Контракты нового процесса

Порядок API-ID: 0 → 2 → 3 → 5 → 6 → 4 → 7. Не запускай старый анализ задания (ID 1). Результат записывается в путь TASK.output; сохраняй предыдущие утверждённые документы и применяй только навыки текущего TASK.

- **0, простое объяснение.** Короткий понятный текст с примером по brief-explanation. `constraints` содержит только точные цитаты прямо заявленных в кейсе ограничений. Без таких ограничений — пустой список. Не придумывай запретов, лимитов, сроков и стандартных ограничений проекта.
- **2, поиск аналогов.** Прежний контракт `02_competitors.md/json`, ссылки и проверяемые цитаты. Сравнивай с исходным кейсом и простым объяснением. Не требуй отдельного формального анализа задания.
- **3, брейншторм.** Примени brainstorm. Сбор идей → документ идеи → по слову «готово» предложение версий и экранов → отдельное подтверждение → публикация с userConfirmed=true. Не заменяй пользовательскую задумку готовой концепцией ИИ.
- **5, моки.** Входы — согласованные идея, версии и экраны. План агентов ещё не создан. Сам подготовь нужные сущности и схемы данных по этим экранам, примеры успешных/пустых/ошибочных состояний и сценарии проверок. Требуются `mocks/fixtures/data.json`, `mocks/scenarios.json`, `mocks/screens.json`, `04_validation_report.md` и все упомянутые локальные JSON Schema. `mocks/screens.json`: `{ "screens":[{"versionId":"v1","screenId":"home","fixtures":["mocks/fixtures/data.json"]}] }`. Перечисли каждый экран каждой версии. Для статического экрана без данных передай fixtures: [] и reason. Не выдумывай требования, отсутствующие в согласованной идее. Данные синтетические; явно отличай моки от работающих интеграций.
- **6, пакет.** Контроллер собирает архив и принимает возвращённый проект. Не подменяй этот шаг планированием агентов.
- **4, планирование.** Уже есть согласованные экраны, моки и возвращённый проект. Изучи его фактический код по пути INPUT.feedback, а затем подготовь архитектуру, контракты, тест-план, `03_tasks.json` и `03_execution.json` по laboratory-planning. План определяет последовательность и параллельные ветви агентов; не запускай реализацию во время планирования.
- **7, агенты.** Выполняют утверждённый граф с отдельными рабочими ветками, независимыми тестами и приёмкой. Не составляют второй, расходящийся с согласованным граф.
