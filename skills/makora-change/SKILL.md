# Изменение артефакта Макоры

Используй конфигурацию текущего проекта из .makora/control.json и его контроллер scripts/makora.py. Не меняй состояние .makora вручную.

1. Получи GET /api/preparation/changes/context. По files и owners найди точный артефакт, например 02_user_flow.mmd. При неоднозначности уточни выбор. Прочитай содержимое и применимый методический навык. Правка User flow — изменение самого Mermaid, а не только заметки рядом с ним.
2. Для предварительного анализа передай POST /api/preparation/changes с request, targets (точные пути), baseDigest и при необходимости files (объект «путь → полное новое содержимое»). Не перезаписывай действующие artifacts/ при подготовке предложения. Если пользователь уже изменил файл на диске, выполни POST /api/preparation/changes/scan с request и targets: контроллер сравнит файлы в artifacts/ с сохранённой версией и создаст предложение. Для файла из другого места прочитай предложенную версию и передай в files; базу возьми из context.
3. Представь пользователю diff и влияние. confirmed означает структурную связь по графу, possible — гипотезу, включая более поздние этапы. Не заявляй, что отсутствие связи доказывает отсутствие влияния. Объясни последствия изменения, например удаление регистрации может затронуть переходы, авторизацию API, фикстуры, тесты и задачи, но подтверждай каждую связь материалами проекта.
4. Предложи обновить связанные артефакты. Для согласованного комплекта создай новое предложение с targets всех меняемых документов и files их новых версий. Сохраняй идентификаторы требований и неизменённые части. Изменение требований пользователя отделяй от исходных требований организатора.
5. После явного подтверждения конкретного diff выполни POST /api/preparation/changes/<id>/apply с {"confirm":true,"reviewStages":[номера выбранных этапов из impact]}. При stale base пересчитай предложение, не обходи проверку. Новые документы требуют отдельного утверждения своих этапов; применение diff не означает успешные тесты приложения.

Другой сервис может вернуть JSON с request, targets, baseDigest, files. Импортируй его через тот же маршрут. Этот навык не получает доступ к произвольным внешним чатам и не запускает код из предложенных файлов.

Для вызова API используй `<repository>/scripts/makora.py --project-root <project> request <route> --json <payload.json>`. Сначала выполни status. Полные инструкции управления доступны в makora-control. Не печатай токен.


При CHANGE_RECOVERY_CONFLICT получи GET /api/preparation/changes/recovery и журнал предложения. Ничего не перезаписывай автоматически. Если пользователь явно выбирает сохранить текущие файлы, передай POST /api/preparation/changes/<id>/recovery с confirm:true и expectedStateHash из отчёта; затем заново выполни scan. Журнал и исходные версии остаются в истории.

При изменении требований передай в proposal.validation актуальные requirementsEvidence; для последующих этапов — coverage по протоколу preparation-session. Контроллер заново проверяет источники и покрытие, прежнее подтверждение не заменяет новую проверку.
