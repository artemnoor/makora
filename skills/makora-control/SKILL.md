# Макора в текущем проекте

Прочитай `.makora/control.json`: repository, projectRoot, port. Используй Python из `<repository>/.venv`, контроллер `<repository>/scripts/makora.py`, передавая `--project-root <projectRoot>` перед командой.

Сначала выполни `status`. Если сервер недоступен — `launch`, затем проверь `status`. При занятом порте другого проекта остановись с объяснением. Сайт открыт на http://127.0.0.1:<port> и использует то же состояние. Для GET: `request /api/preparation` или `request /api/agents/state`. Для POST запиши UTF-8 JSON в файл и выполни `request <route> --json <file>`. Токен контроллер получает сам; не печатай и не сохраняй его.

Свободные инструкции пользователя сопоставляй с текущими этапами и доступными навыками. Отвечай здесь, изучая input/, artifacts/, reports/ и app/. Не сбрасывай проект ради нового сообщения. Не редактируй файлы состояния `.makora` вручную.

При просьбе изменить существующую схему, User flow, документ, API или моки применяй навык makora-change. Он создаёт предложение и анализ влияния до перезаписи артефактов. Для уже изменённого пользователем файла передай его содержимое как предложение.

## Новый порядок (workflowVersion=3)

Номер на доске отличается от API-ID. Порядок: 01 объяснение (0), 02 аналоги (2), 03 брейншторм (3), 04 моки (5), 05 пакет (6), 06 планирование (4), 07 агенты (7). Этап 1 — сохранённая история старого анализа; не запускай его.

- POST /api/preparation/0/start с brief и openInCodex:true — короткое пояснение. constraints содержит только точные цитаты явно заявленных ограничений; при их отсутствии список пуст. После проверки утверди этап через /0/approve.
- /2/start — поиск аналогов. /api/preparation/2/pdf выгружает сравнение. /api/preparation/idea/start с openInCodex:true допускает переход с непроверенными аналогами, не называя их проверенными.
- Брейншторм ведётся в обычном чате Codex: идеи пользователя постепенно становятся idea-draft.md. «Готово» завершает сбор идей. Затем предложи отдельный versions-draft.md с версиями и полными экранами каждой версии. Попроси отдельное подтверждение («да» или «подтверждаю версии»). До него не публикуй финальные files; смотри навык brainstorm. /3/refresh подхватывает подтверждённые документы.
- /5/start создаёт моки под согласованные идею и экраны, без ещё не существующего плана агентов. После проверки /5/approve.
- /api/preparation/package и /api/preparation/archive формируют прежний пакет для внешнего агента. После возврата ZIP и /api/preparation/result/continue переходи к планированию (4), а не сразу к разработке.
- /api/preparation/planning/preferences с laboratories: [описания функций] задаёт пожелания человека; лаборатории необязательны.
- /4/start — планировать по возвращённому проекту: каркас, основная ветка, лаборатории и отдельные задачи подключения. /api/preparation/planning/execution с tasks и execution сохраняет отредактированный граф; после правок его нужно заново утвердить через /4/approve.
- /api/preparation/development с stage:7 создаёт очередь из утверждённого графа без повторного планировщика. Ветви запускаются через существующий runtime Махораги. Лабораторные мини-интерфейсы проверяет человек; до подключения функция заменяется моками. /api/agents/runs/<run>/laboratories/<id>/preview запускает локальный тестовый интерфейс; /accept подтверждает проверенные задачи для текущего хеша кода. Тестовый UI не переносится в основную ветку.
- /api/preparation/<stage>/open-codex повторяет открытие существующего Desktop-чата без отправки задания.
- Модели и рассуждения каждой роли настраиваются через /api/preparation/agent-settings. Сохраняй остальные роли и используй доступный каталог моделей.

Не редактируй состояние .makora вручную. Установленные проекты v2 сохраняют свои документы; при переходе к v3 обсуждение идеи и план требуют нового согласования. Статусы проверок не заменяют человеческую приёмку.
