# Локальная основа агентной системы

Ядро хранит согласованные артефакты первого рабочего маршрута и обеспечивает повторяемую ручную итерацию с внешним ИИ. Встроенная модель не вызывается. Код возвращённого проекта никогда не запускается автоматически.

Нужен Python 3.11 или новее. Для локального цикла сайта запусти сервер с каталогом статики и путём хранения вне репозитория:

```sh
python -m makora_core.server --static dist --workspace ~/.makora/workspace --host 127.0.0.1 --port 8000
```

Сервер можно поднять отдельно на 8765, оставив статический сервер на 8000. Браузерный интерфейс проверяет оба локальных адреса и показывает, когда API недоступен. Не помещай конфиденциальные файлы в публичный репозиторий.

`makora_core.iterations.IterationStore` сохраняет каждую ревизию и архив итерации в `state/iterations/`, а индекс — в `state/iterations/index.json`. Контент ревизии не перезаписывается; откат создаёт новую запись. Один локальный API-процесс сериализует операции через блокировку потока.

```sh
python -m makora_core init /path/to/workspace
python -m makora_core skills
```

Поместите документ или извлечённый текст в `input/`, затем зарегистрируйте и явно подтвердите его:

```sh
python -m makora_core register /path/to/workspace INPUT-001 input/brief.txt text
python -m makora_core approve /path/to/workspace INPUT-001 --note "Проверен исходный документ"
python -m makora_core prepare /path/to/workspace requirements-analysis --artifact INPUT-001 --task "Разобрать задание" --output requirements.yaml --success "Подтверждённые требования имеют источники"
```

`prepare` возвращает пакет вызова и статус `not_started`; он не запускает скилл и не анализирует документ. `register` регистрирует существующий файл в `input/` или `artifacts/`, поддерживает `--depends-on ID` и `--source` многократно. `audit` сравнивает содержимое файлов с сохранёнными версиями и помечает зависимые результаты как требующие перепроверки. `approve` фиксирует решение; подтверждённый результат можно передать в `prepare`.

Архивы ZIP проверяются до регистрации: лимиты количества/размеров, коэффициента сжатия, CRC, запрет абсолютных путей, `..`, дубликатов и symlink. Ничего не извлекается в проектный каталог. Текст сравнивается diff; бинарные файлы — размером и SHA-256. Однозначный перенос с неизменным содержимым и заявленный `rename` с исходным путём показываются одним изменением. Незаявленный перенос с изменением содержимого может отображаться как удаление и добавление.

На основе текущих документов создаётся `artifact-registry.json`: ID, пути, источники и ссылки из структурированных задач и сценариев. Связи из согласованных файлов участвуют в обязательной перепроверке. Связи из неподтверждённых файлов и совпадений в таблицах, а также выводы по пути — предположения и не блокируют согласование. Если документы не содержат ID или ссылок, недостающие связи не придумываются. При сравнении служебный контекст передачи исключён; отсутствующие в ответе документы и моки сохраняются из базовой версии, если их удаление не заявлено явно.

Решения по файлам и документам, ответы на вопросы, базовые контрольные суммы, результаты форматных проверок и импортированные ZIP сохраняются локально. Устаревшая базовая ревизия, неразрешённые зависимости, открытые обязательные вопросы, неутверждённые документы и ошибки их проверки блокируют выпуск новой версии. `prototype-report.json` и результаты команд внешнего агента считаются заявленными им фактами и не запускаются повторно.

Для PDF и изображений извлечение текста не реализовано. Содержимое ссылки на проект не скачивается. Семантическое сравнение, запуск кода в изолированной среде и автоматический импорт произвольных форматов задач пока не реализованы.
