# Модели, роли и конфигурация проекта

[← Файлы и состояние](artifacts-and-state.md) · [README](../README.md) · [API и контроллер →](api.md)

Настройки модели относятся к конкретному проекту и роли. Модель текущего разговора в Codex Desktop выбирается в самом Desktop; переключатель Макоры не переписывает уже открытый чат.

## Модели и рассуждения

Откройте «Модели» / настройки моделей и рассуждений в шапке или соответствующий раздел доски разработки. Выберите роль, модель из текущего каталога Codex и доступный уровень рассуждений.

Список моделей и допустимых уровней берётся из локального каталога, а не зашит в руководство. Значение `reasoningEffort:null` оставляет уровень по умолчанию модели. Кодовая настройка при отсутствии профиля — `gpt-6-luna`; наличие этой модели в вашем каталоге всё равно проверяется.

Недоступная модель не должна автоматически заменяться другой с объявлением успешного выполнения. Ошибку выбора нужно исправить в настройках.

## Роли профиля

| ID | Назначение |
| --- | --- |
| `preparation` | Этапы подготовки и их чаты Desktop |
| `builder` | Исполнитель задач разработки |
| `test_designer` | Независимый автор тестов |
| `reviewer` | Проверка текущего результата |
| `mahoraga_orchestrator` | Координация разрешённых действий очереди |
| `mahoraga` | Специалист для сложной проблемы |
| `mahoraga_planner` | Планировщик отдельных/совместимых runtime-сценариев; основной v3 использует утверждённый граф |
| `project_chat` | Сохранённая совместимость профиля прежнего проектного чата |

Не все сохранённые роли означают наличие одноимённого пользовательского экрана. Общего чата с Макорой на сайте текущего процесса нет.

## Когда применяется изменение

Настройки используются при создании последующей сессии соответствующей роли. Уже начатый ответ продолжает выполняться с прежними параметрами. Для подготовки после смены модели/уровня может потребоваться новый чат при повторном запуске этапа; старый чат не исчезает.

Изменение модели не изменяет документы, не утверждает этап и не снимает проверки кода. Сохранение API-профиля требует актуального `projectId`, чтобы настройки не попали в другой проект из устаревшей вкладки.

## Файл управления

`<проект>/.makora/control.json` содержит:

```json
{
  "projectRoot": "C:\\Projects\\Campus",
  "repository": "C:\\Projects\\Campus\\makora",
  "port": 8000
}
```

Это пример, а не файл, который нужно бездумно скопировать в уже установленный проект. Установщик записывает фактические пути. Контроллер сверяет корень с сервером перед работой.

Разные одновременно запущенные проекты требуют разных портов. Изменение пути или порта в одном файле не переносит данные и не останавливает прежний процесс.

## Навыки

Источники навыков находятся в репозитории `skills/`, установленные проектные копии — в `.agents/skills/`. Конкретная сессия подготовки получает снимки нужных пакетов с хешами в `skill-snapshots/`. Изменение исходного навыка не подменяет задним числом инструкции завершённой сессии.

Текущие чаты подготовки создаются через Desktop. Навыки передаются как инструкции и ссылки на файлы (`prompt-referenced`); это не нативные `skill inputs` отдельного App Server. Фоновые агентные сценарии могут использовать нативные входы. Наличие ссылки или принятого API-входа ещё не доказывает выполнение всей методики — проверяются результаты.

Повторная установка добавляет отсутствующие папки навыков. Существующие пользовательские копии нужно обновлять осознанно, сохраняя локальные правки и резервные копии.

## Параметры сервера для разработки

| Параметр | Назначение |
| --- | --- |
| `--project-root` | Единственный текущий проект Codex |
| `--workspace` | Служебные индексы локального сервера |
| `--static` | Каталог `dist` для сайта на том же сервере |
| `--host` | Обычно `127.0.0.1` |
| `--port` | Локальный порт |
| `--agent-root` | Дополнительный разрешённый Git-корень для runtime; может повторяться |

При запуске установленным контроллером `workspace` выбирается внутри проекта. Для серверного CLI без этого контроллера есть переменная `MAKORA_WORKSPACE`; не путайте её с корнем самого продукта.

Продвинутые параметры моста — `CODEX_HOME`, `CODEX_APP_SERVER_BINARY`, `CODEX_APP_TOOLS_CONTEXT_THREAD_ID`, `CODEX_APP_TOOLS_PIPE_PATH` и `MAKORA_WINDOWS_SANDBOX`. Их назначение и границы описаны в исходниках интеграции. Обычно установленные из Desktop процессы получают нужный контекст автоматически; ручное изменение этих переменных не является первым способом исправления ошибки этапа.

## Авторизация

Вход в Codex и токен локальной страницы — разные вещи. Первый нужен для моделей, второй защищает изменяющие запросы локального сервера. Не копируйте данные входа Codex в репозиторий, скриншоты настроек или примеры API.

Индикатор входа на сайте проверяет состояние аккаунта через локальный мост. При подтверждённой проблеме входа доступно восстановление. Недоступность сервера сама по себе не означает, что нужно снова проходить вход.
