# Установка и первый проект

[README](../README.md) · [Маршрут проекта →](workflow.md)

Макора работает с одной папкой проекта Codex Desktop. Сайт показывает доску и документы, а обычные чаты Codex используются для пояснения кейса, поиска аналогов, брейншторма и подготовки материалов. Для разработки используются отдельные агентные рабочие сессии.

## Что потребуется

| Компонент | Для чего нужен |
| --- | --- |
| Codex Desktop с действующим входом | Создание чатов подготовки и доступ к моделям |
| Windows и PowerShell 7 (`pwsh`) | Основной сценарий установки и локальный мост Desktop |
| Python 3.11+ | Сервер, проверки документов, PDF и контроллер |
| Node.js 22.13+ и npm | Локальный мост, Mermaid и браузерные проверки |
| Git | Репозиторий и отдельные рабочие ветки агентов |

CI запускается на Linux, но это не означает поддержку Desktop-интеграции на всех ОС: текущий мост использует механизмы Windows. Вызовы моделей расходуют доступные лимиты Codex. Настройка моделей описана в [конфигурации](configuration.md).

## Установка через Codex

1. Создайте папку будущего проекта и откройте её в Codex Desktop.
2. Отправьте в чат:

   > Склонируй https://github.com/artemnoor/makora.git в подпапку makora. Прочитай AGENTS.md и установи Макору для текущей папки проекта через setup.ps1. Запусти локальный сервер, проверь состояние и дай ссылку. Для управления проектом используй навык makora-control.

3. Откройте полученную локальную ссылку. По умолчанию это `http://127.0.0.1:8000`.

Установщик создаёт окружение Python, устанавливает Python/npm-зависимости, добавляет проектные навыки и инструкции в `AGENTS.md`. Он не создаёт второй проект Desktop и не переносит авторизацию Codex в репозиторий.

## Установка вручную

Пример ниже использует вымышленную папку `C:\Projects\Campus`. Выполняйте команды из PowerShell 7:

```powershell
Set-Location 'C:\Projects\Campus'
git clone https://github.com/artemnoor/makora.git makora
Set-Location makora
./setup.ps1 -ProjectRoot 'C:\Projects\Campus'
```

Для другого порта:

```powershell
./setup.ps1 -ProjectRoot 'C:\Projects\Campus' -Port 8001
```

Указывайте родительскую папку проекта, а не подпапку `makora`, если репозиторий установлен именно в неё. Конфигурация записывается в `<проект>/.makora/control.json`.

## Проверка установки

Из папки репозитория:

```powershell
./.venv/Scripts/python.exe scripts/makora.py --project-root 'C:\Projects\Campus' status
```

Контроллер сверяет папку проекта с сервером на указанном порте. Если порт обслуживает другой проект, нельзя продолжать работу с его состоянием: сначала выберите правильный порт или остановите именно тот сервер, который больше не нужен.

Для повторного открытия сервера:

```powershell
./.venv/Scripts/python.exe scripts/makora.py --project-root 'C:\Projects\Campus' launch
```

`launch` проверяет уже запущенный сервер и запускает новый, если сервер недоступен. Эта команда не является командой принудительного перезапуска.

## Первые действия на доске

1. Загрузите кейс или вставьте его текст.
2. Запустите простое объяснение. Отдельный анализ задания больше не требуется.
3. На доске появятся семь этапов. Нажмите на этап, чтобы открыть его содержание на весь экран.
4. Проверьте пояснение и цитаты ограничений, затем продолжайте к аналогам.
5. Когда дойдёте до брейншторма, переходите в созданный чат **в том же проекте Codex**.

Доска не содержит собственного чата для обсуждения идеи. Все идеи пишутся в Codex; сайт показывает согласованные документы и состояние работы.

## Файлы кейса

Поддерживаются PDF, DOCX, TXT и Markdown. В интерфейсе загрузки указан предел 20 МБ; извлечённый текст ограничен 100 000 символов. PDF со сканами без текстового слоя требует предварительного OCR. Контроллер не распознаёт изображение страницы как текст автоматически.

Если PDF перенёс предложение на несколько строк, это само по себе не делает цитату ограничения неверной: проверка допускает различия пробелов и переносов, сохраняя совпадение слов, чисел и пунктуации.

## Обновление установленного проекта

1. Сохраните свои изменения в репозитории, если вы меняли код Макоры.
2. В подпапке `makora` выполните `git pull --ff-only`, затем установите зависимости из `requirements.txt` и `npm ci` при их изменении.
3. Штатно остановите сервер и запустите его через контроллер. Обновите страницу.
4. Если менялись навыки, поручите Codex сверить установленные `.agents/skills` с обновлёнными `skills/`, сохранив ваши настройки и резервные копии изменённых инструкций.

Повторный `install` добавляет отсутствующие навыки, но не перезаписывает существующие папки навыков. Простого `git pull` недостаточно для обновления уже загруженных Python-модулей работающего сервера. Не удаляйте `.makora` ради обновления: там состояние и история проекта.

Не останавливайте все процессы Python, Node.js или Codex одновременно. Если сервер был запущен в отдельном терминале, используйте `Ctrl+C` в этом терминале. Для фонового сервера сначала установите, какой процесс обслуживает порт и к какому проекту относится его командная строка.
